# .claude/all

Darwin's local hooks, the same in every repo. **Do not edit a copy:** the single source is
`admin-darwin-agents/templates/context/claude-all/`, rolled out to every repo.

| File | Hook | What it does |
|---|---|---|
| `darwin-tick.sh` | UserPromptSubmit | counts messages locally and says when a check is due (every N messages, by chance, or when the prompt matches a check's `trigger`, e.g. a report or plan calls Robin); the table of checks is fetched from the agent center once a day and cached in `~/.cache/darwin/` |
| `darwin-brain.sh` | UserPromptSubmit (and land() step 0) | the person's second brain tags, at most once every 2 h across all their chats: one clock in `~/.cache/darwin/second-brain.last`, the first chat past 2 h fetches (never pulls), lists the tags not yet handled and resets it, the others stay quiet; the first message of every chat also shows the pending tags from the last fetch (no network, clock untouched); tags reach the person as a `systemMessage` banner and the reply opens with a `## Second brain` heading; nothing pending, nothing said; the chat offers to file them and keeps its job (row 047); a tag not shown before is marked NEW in the banner and on the page. The first chat of the day also builds the daily page `<brain>/local/second_brain_report/index.html` in the background (the served `second_brain_report.py`) and opens it in the browser, the one standing exception to DON'T #16; `DARWIN_BRAIN_PAGE=0` turns the page off (the banner stays) and the page is never committed. Later chats keep the banner and the offer to file every pending tag; the page is built from the locally cached builders (no cache: the agent is asked to call `kb_planning_builders()`). land() step 0 runs it with the brain's name, which it records for the hook. In that mode it also says, every time, when the brain is not cloned (ask the person, clone on a yes, rerun) or has unsaved work (uncommitted files or commits not pushed), and on a Thursday or Friday, once a day, offers the weekly report when this week's `report.pdf` is missing locally and on the remote. `darwin-brain.sh <brain> --save "<message>"` saves the brain in one step (row 051): commits everything but `local/` with the person's git identity, pulls with rebase and pushes (a tracked file the exclude rules hide, such as a private report over a saved week, is unstaged and reported as skipped); on a conflict it keeps the commit local, never forces. Autosave: every 25 messages of a chat (`DARWIN_BRAIN_SAVE_EVERY`) the hook runs that same save in the background when the brain has unsaved work, so it goes up without the agent remembering; a failure is reported once at the next message; `DARWIN_BRAIN_AUTOSAVE=0` opts out |
| `darwin-guard.sh` | PreToolUse | while a STOP is open, refuses commits, pushes (`git -C` too), deploys and sending, except the second brain save alone (`bash .claude/all/darwin-brain.sh admin-second-brain-<id> --save '<message>'`, nothing chained); always refuses a hand-made report page (an .html or .pdf written by hand anywhere in `planning/reports/` or at the repo root) and any commit of a report page at the repo root; other reading and editing stay free |
| `darwin-report.sh` | PostToolUse | after every Bash, Write or Edit: refuses a report page in `planning/reports/` (or a report page at the repo root) without the planning builders' stamp, whatever wrote it; a copy of a built page at the root is a review copy, added to `.git/info/exclude` (never committed); the first action of a session on `planning/` or a page calls Robin's report check |
| `darwin-done.sh` | (run by the session) | closes a STOP once it is fixed: `bash .claude/all/darwin-done.sh <check> fixed` |

The scripts are stable: which checks exist, how often and where is data in the agent center
(ADR-0010), so changing a check never needs a rollout.
